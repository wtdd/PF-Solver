# Data_Generation

This directory contains the data-generation code and raw IEEE system input files.

## Main Files

| Path | Description |
| --- | --- |
| `Slover_Gen_Data.cpp` | C++ generator for the common CSV datasets. It builds admittance/Jacobian information and generates training, in-distribution/extrapolation-grid, and N–R numerical-failure stress-test samples. |
| `IEEE_14/bus.txt` | IEEE-14 bus input file. |
| `IEEE_14/line.txt` | IEEE-14 branch input file. |
| `IEEE_14/gen.txt` | IEEE-14 generator input file. |
| `IEEE_118/bus.txt` | IEEE-118 bus input file. |
| `IEEE_118/line.txt` | IEEE-118 branch input file. |
| `IEEE_118/gen.txt` | IEEE-118 generator input file. |
| `ThreadPool.h` | Windows thread-pool helper used by the generator. |
| `Structure.h` | Power-system data structures and shared declarations. |
| `nicslu.h`, `nics_common.h` | NICSLU API headers required by the sparse Newton-Raphson solver. |

## Generated Output

The generator writes common CSV files expected by the Python methods:

```text
../Data/<system_name>/
  meta.csv
  bus_static.csv
  branch_static.csv
  ybus.csv
  bus_state.csv
  jacobian_start.csv
  branch_flow.csv
```

## Configuration

Important configuration values in `Slover_Gen_Data.cpp` include:

```cpp
string chose_node = "IEEE_118";
#define bus_total 118
#define need 120
int sample_num = 20000;
int each_injection = 2;
double injec_min = 0.001, injec_max = 0.20;
double theta_eps_min = 1e-6, theta_eps_max = 0.10;
double V_eps_min = 1e-6, V_eps_max = 0.10;
const double X_SCORE_MIN = -2.0, X_SCORE_MAX = 2.0;
const double PQ_SCORE_MIN = -2.0, PQ_SCORE_MAX = 2.0;
const double SCORE_STEP = 0.2;
int each_cell = 10;
int max_try_per_cell = 3000;
#define max_iter 10
const int ill_target_total = 100;
const int ill_base_pf_max_iter = 30;
const int ill_verify_max_iter = 50;
```

`max_iter` is used by the training/grid stages; the three `ill_*` constants configure the stress-sample stage separately.

When switching systems, update at least:

- `chose_node`;
- `bus_total`;
- `need`, which is the fixed array capacity and must remain larger than `bus_total`;
- `path`, which points to the raw `bus.txt`, `line.txt`, and `gen.txt` input folder;
- `datapath`, which points to the output `Data/` folder.

The current source file contains local Windows paths from the original experiment environment. These paths must be edited before regenerating data on a new machine.

The reduced CSV files committed under `Data/` were prepared for repository inspection and do not reflect the full output size implied by the generator defaults above. The complete datasets used by the logged experiments contain 40,000 train/validation samples, 4,000 in-distribution/extrapolation-grid cases, and 100 N–R-selected numerical-failure stress cases per system.

## Dataset Construction Details

The generator builds three types of samples: training samples, in-distribution/operating-condition-extrapolation grid samples, and N–R numerical-failure stress-test samples.

### Training Samples

Training data is generated by perturbing both the operating condition and the initial power-flow state:

- `sample_num = 20000` controls the number of base operating-condition samples attempted in the current configuration.
- `each_injection = 2` controls how many initial-state perturbations are sampled for each successfully solved base operating condition.
- Active/reactive power injection perturbation magnitude is sampled from `injec_min = 0.001` to `injec_max = 0.20`.
- Initial angle noise is sampled logarithmically from `theta_eps_min = 1e-6` to `theta_eps_max = 0.10`.
- Initial voltage noise is sampled logarithmically from `V_eps_min = 1e-6` to `V_eps_max = 0.10`.

In short, the training set covers moderate P/Q operating-condition perturbations and noisy initial states around converged AC power-flow solutions. A record is written only after both the perturbed operating point and the sampled starting state pass the generator's N–R verification. The default configuration therefore produces at most `sample_num * each_injection = 40,000` records.

### In-Distribution and Operating-Condition-Extrapolation Grid Samples

Grid test samples are generated after the training set is completed. The generator first records the maximum training perturbation scale, then samples normalized perturbation scores over a two-dimensional grid:

- X-axis score range: `[-2.0, 2.0]`.
- PQ-axis score range: `[-2.0, 2.0]`.
- Grid step: `0.2`.
- Target samples per grid cell: `each_cell = 10`.
- Maximum attempts per grid cell: `max_try_per_cell = 3000`.

Here, the X score measures the normalized initial-state perturbation scale, while the PQ score measures the normalized injection perturbation scale. The interval `[-1, 1]` corresponds to the training-scale region used for in-distribution evaluation, while cells outside that range provide operating-condition extrapolation tests (`OOD-X`, `OOD-PQ`, and `OOD-X+PQ` in the implementation). The default target is `20 x 20 x 10 = 4,000` cases. If a cell cannot supply ten valid cases within 3,000 attempts, the generator reports a warning and the generated total can be smaller.

### N–R-Selected Numerical-Divergence Stress Samples

For every candidate, the generator first obtains a valid reference PF solution from a flat start within `ill_base_pf_max_iter = 30` iterations. It then perturbs the initial voltage state and verifies conventional full-step N–R PF for up to `ill_verify_max_iter = 50` iterations.

Only two statuses are retained:

- `LINEAR_FAIL`: Jacobian analysis, factorization, or the linear solve fails;
- `DIVERGED`: the state or residual becomes non-finite, or satisfies the implemented residual-growth checks.

`CONVERGED`, `SETUP_FAIL`, and ordinary `MAX_ITER` outcomes are rejected; reaching the iteration limit alone is not sufficient for inclusion. The X/PQ search range is expanded when needed until the target of 100 accepted stress cases is reached.

## Generation Logic

The generator follows this high-level workflow:

1. Load bus, branch, and generator files.
2. Build the admittance matrix and Newton-Raphson Jacobian.
3. Generate training samples by perturbing operating conditions and initial states.
4. Generate heatmap test samples over the configured X/PQ region grid.
5. Search for conventional full-step N–R linear-solver failures or clear numerical divergence from selected starting points.
6. Write all samples to the common CSV schema used by the Python loaders.

## Build Notes

The C++ code is Windows-oriented and uses Windows APIs such as events and critical sections. It depends on the included headers plus the external NICSLU library binary. No ready-made Visual Studio project or portable build script is included, so configure the include path, library path, and linker input in your own x64 build environment. NICSLU licensing and redistribution requirements should be checked before publishing or redistributing its binary.
